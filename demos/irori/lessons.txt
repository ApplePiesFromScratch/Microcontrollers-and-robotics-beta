@ /* ---------------------------------------------------------------- input: events
Input: events, one a latch
WHAT    : a queue of events (os_push); apps read one event a latch, so two presses in one latch are two events, not one.
@ /* ---------------------------------------------------------------- the hands' roles
The hands' roles and presets
WHAT    : which button does what is a setting (a role), not wiring. Presets set roles in one step; keys_mode for the keyboard.
@ /* ---------------------------------------------------------------- the keeping
THE KEEPING: two copies, each with a sum; a keeper mends; changes save themselves
WHAT    : settings live in two copies, each with an FNV sum. At boot the good copy is loaded; keeper_turn rewrites a bad copy
          from the good one; autosave_latch saves a change after it has stood still a while. carry_v1 reads IRORI 1's layout.
WHY     : flash can be cut mid-write by a power-off. Two copies and a sum make that a reading (which copy is good), not a loss.
@ /* ---------------------------------------------------------------- pins: the user's GPIOs, and who else uses them */
PINS AND THEIR OWNERS: the board map as a relation, asked every time
WHAT    : the user's pins are GPIO 0, 1, 2, 3, 8, 9, 20, 21. pin_user(pin, me) answers who else owns a pin, in a stated order:
          hands, I2C (8 and 9), SERVO, TIMER, RULES, then PINS. pin_apply refuses to touch a pin someone else owns.
RELATION: "pin 8 is I2C" is not a property of pin 8. It holds while I2C is on, and the answer is computed from the settings
          each time, so changing one setting can never leave two owners on one pin.
ANALOG  : is_analog(pin) is pin <= 4: ADC1 on the C3 is GPIO 0-4 (docs/BOARD_MAPPING.md section 2).
TRY     : do practice/p11_board_map, then compare your map's owners with pin_user's order.
@ /* ---------------------------------------------------------------- the frame: bars, home, windows, forms */
The frame: bars, home, windows, forms
WHAT    : the clock text shows clock_total, a sum of measured changes (section 19), never a wall time read directly.
@ /* ---------------------------------------------------------------- the hands: buttons and stick as readings
The hands: readings turned into events by the roles chosen
WHAT    : a press is counted between two latches (taps), a hold is a run of latches, a long hold is a longer run. The event a
          press makes depends on the role chosen for that button.
FOUND   : hands_reset must leave each button as already-down (bt_was = 1), or a button held through a reset fires a press.
          A press counted while down starts a new hold. home() was consuming keys meant for the keyboard (IRORI 2 notes).
@ /* ---------------------------------------------------------------- readings: a value and its change, and rate(A, B) */
Readings: a value and its change; rate(A, B)
WHAT    : read_pin returns a reading with its change since the last latch. rate_of(A, B) divides A's change by B's change and
          answers theta when B did not move, shown by name on the PLOTTER.
@ the applications */
The applications: PINS, PLOTTER, SERVO, RULES, TERMINAL, I2C SCAN and the rest
WHAT    : each app has an app_* (draw and answer events) and a tick_* that runs even when the app is not in front, so
          several run at once. RULES: WHEN something THEN something, eight rules kept with the settings.

@ /* ---------------------------------------------------------------- one latch of the OS */
One latch of the OS
CLOCK   : dclock = now - clock_last; clock_total += dclock. The clock is read only as its change, and every timer in the OS
          counts down by dclock: no app holds a wall time (the project's no-independent-variable rule, at the OS level).

@ // ---------------------------------------------------------------- the hardware layer IRORI asks for
The hardware layer: the board's answers to hal_*
WHAT    : i2c_check protects the bus pins before probing; hal_store_* keeps the two copies in flash.
@ // ---------------------------------------------------------------- hands: each button counted
Buttons counted by interrupt, debounced by time
WHAT    : bt_isr counts a press on the falling edge, ignoring edges within 25 ms of the last (debounce by time, in micros).
          hal_buttons catches up an edge lost inside a bounce from the level, so a tap shorter than a latch is not lost.
TRAP    : the interrupt and the latch share counters, so both sides take bt_mux. Remove the critical section and a press
          can be counted twice or lost when the ISR fires mid-read.
@ // ---------------------------------------------------------------- starts that followed trouble
Starts that followed trouble
WHAT    : trouble_n counts panic, watchdog and brownout resets in a row, in RTC memory that survives a reset but not a power-off.
          Three in a row, or A or B held at power-on, and the OS starts safe (no profile, no ghost), so a bad setting cannot lock
          the board in a reset loop.
